# Platform-native adaptation matrix

Treat these as editorial tendencies, not fixed algorithm rules. Verify current technical limits when precision matters.

| Format | Reader/viewer intent | Suggested structure | Quality check |
|---|---|---|---|
| Professional network post | Learn, compare, discuss work | Specific observation → lesson → example → thoughtful question/CTA | Is it concrete and credible rather than self-congratulatory? |
| Short-form video | Understand one idea quickly | Visual hook → one promise → 2–4 beats → example → clear close | Can it be understood without exaggerated claims? |
| Newsletter | Build context and trust | Human opening → useful idea → evidence/example → action/resource | Does it deliver value beyond a social post? |
| Blog/article | Search and reference | Clear answer → sections → examples → sources → limitations | Is each section answering a real reader question? |
| Community/forum | Solve a real problem | Context → what was tried → useful detail → invitation for specific feedback | Does it respect community rules and avoid disguised spam? |
| Product update | Help existing users act | What changed → who benefits → how to use → caveats | Does it describe shipped behavior only? |

## Reuse rules
- Preserve the original meaning, caveats, and credit.
- Make the opening specific to each audience.
- Avoid copying the same CTA to every channel.
- Treat view count, reach, saves, clicks, signups, and sales as different metrics.
